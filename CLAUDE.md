# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`vue-html-to-paper` is a small npm plugin that prints a DOM element. It copies the element's `innerHTML` into a new window, adds stylesheet `<link>`s, and calls `window.print()`. One package supports **Vue 2.6, Vue 2.7 and Vue 3** (peer dependency `vue: ^2.6.0 || ^3.0.0`). The `v1` branch is the old Vue 2-only 1.x line.

## Commands

Node version: `.nvmrc` (24). Package manager: npm (`package-lock.json`).

- `npm test`: Vitest + jsdom. Run a single file with `npx vitest run test/api.test.js`, or a single test with `npx vitest run -t "resolves to true"`.
- `npm run test:types`: `tsc` against `test/types/vue3` and `test/types/vue2`. These are separate projects because Vue 2's and Vue 3's global types conflict. The vue2 project maps `vue` to the `vue2` alias via `paths`.
- `npm run build`: Rollup 4 writes `dist/index.mjs` (ESM), `dist/index.js` (CJS, `exports.default` plus named exports), `build/vue-html-to-paper(.min).js` (UMD global `VueHtmlToPaper`), and copies `types/index.d.ts` to `types/index.d.mts`.
- `npm run test:smoke`: loads every built bundle (needs a build first).
- `npm run test:package`: `@arethetypeswrong/cli --pack`.
- `npm run lint`: ESLint 10 flat config (`eslint.config.mjs`), with `--fix`.

CI (`.github/workflows/ci.yml`) runs all of the above on Node 22 and 24. It also fails if `git diff -- dist build types` is non-empty after a build.

## Architecture

- `src/index.js` is the whole library. `createHtmlToPaper(globalOptions)` returns the print function `(el, localOptions, cb) => Promise<boolean>`. `install(app, options)` registers it as `app.config.globalProperties.$htmlToPaper` (plus `app.provide('htmlToPaper')`) when given a Vue 3 app, or as `Vue.prototype.$htmlToPaper` when given the Vue 2 constructor. It also stores it in a module-level variable that `useHtmlToPaper()` returns. `htmlToPaper` is a standalone instance with default options. Nothing imports `vue` at runtime.
- Options merge "defined wins": `DEFAULT_OPTIONS`, then the global options, then the local options; `undefined` values are skipped.
- Print flow: `document.write` a `<!DOCTYPE html>` document with the escaped title and `element.innerHTML`, append the style links, call `document.close()` (without it Chrome never opens the print dialog), then after `timeout` ms call `print()`, schedule `close()` if `autoClose`, run `cb`, and resolve `true`.
- `src/umd.js` is the UMD entry only. It attaches the named helpers to the default plugin object so the browser global stays a usable plugin.
- `types/index.d.ts` is hand-written; keep it in sync with the runtime API. `types/index.d.mts` is generated by the build.

## Constraints

- **The source must stay ES2018.** The bundles are not transpiled, and webpack 4 (Nuxt 2, Vue CLI 4) cannot parse `?.` or `??`. ESLint enforces `ecmaVersion: 2018` for `src/`.
- **Build outputs are committed.** Rebuild and commit `dist/`, `build/` and `types/index.d.mts` along with any change to `src/` or `types/`. CI checks this.
- Tests fake `window.open` with `test/popup.js`, which parses whatever the plugin writes into a real Document. Vue 2 tests use the `vue2` (2.7) and `vue26` (2.6) npm aliases. They give each test a fresh `Vue.extend()` subclass, because `Vue.use()` installs a plugin only once per constructor.
- `index.html` is the demo (GitHub Pages). It loads `./build/vue-html-to-paper.js`, so build first and serve the repo root over HTTP.

## Style

`eslint.config.mjs` enforces: semicolons; a space before function parens (`function foo ()`, `install (app)`); keyword spacing; trailing commas on multiline literals; `arrow-body-style`.
